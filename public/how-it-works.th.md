# PTG TH Player Feedback · วิธีการทำงาน

คู่มือนี้อธิบายเป้าหมาย แหล่งข้อมูล กฎ และวิธีอัปเดตแดชบอร์ด ใครก็ตาม (คนหรือ AI) ที่มารับช่วงโปรเจกต์นี้ควรอ่านให้จบก่อนแก้ข้อมูลหรือหน้าจอ

แดชบอร์ดมีปุ่มสลับภาษา VI / EN / TH ในโหมดภาษาไทย ข้อความความคิดเห็นจะแสดงเป็นต้นฉบับภาษาไทยจากแหล่งที่เก็บข้อมูลโดยตรง (ไม่ได้แปล) คำแปลภาษาไทยของส่วนติดต่อผู้ใช้อยู่ใน `public/i18n/th.json`

ข้อความภาษาอังกฤษของความคิดเห็นเก็บไว้ใน `text_en` / `summary_en` ส่วนภาษาเวียดนาม (`text_vn`) ยังเป็นข้อมูลหลัก ข้อความหน้าจอภาษาอังกฤษอยู่ใน `public/i18n/en.json`

- แดชบอร์ด: https://tiennn3.github.io/PTGTHPlayerSentiment/
- คู่มือนี้ (เวอร์ชันดิบสำหรับ AI): https://tiennn3.github.io/PTGTHPlayerSentiment/how-it-works.md
- Repository: https://github.com/TienNN3/PTGTHPlayerSentiment (branch `main` ดีพลอยอัตโนมัติด้วย GitHub Actions → GitHub Pages)

## 1. เป้าหมาย

ช่วยให้ทีมดูแลเกม Play Together VNG ประเทศไทยเห็นภาพได้เร็วในทุกวันว่า:

- เมื่อวาน 7 วันล่าสุด หรือ 30 วันล่าสุดมีความคิดเห็นเข้ามาเท่าไร และแนวโน้มโดยรวมเป็นอย่างไร
- ผู้เล่นกำลังทำอะไรอยู่ (ถามคำถาม แชร์ ร่วมกิจกรรม แจ้งบั๊ก ซื้อขาย…) และคีย์เวิร์ดไหนถูกพูดถึงมากที่สุดในแต่ละวัน
- ผู้เล่นชอบอะไร ไม่พอใจอะไร และบั๊ก / เกมเด้ง / ปัญหาบัญชีเรื่องไหนที่ต้องดำเนินการ
- แต่ละกลุ่ม แฟนเพจ ช่อง YouTube และสโตร์มีความคิดเห็นเข้ามาเท่าไร
- อ่านคำแปลภาษาเวียดนามก่อน แล้วค่อยดูต้นฉบับภาษาไทย พร้อมลิงก์ไปยังแหล่งที่มาเสมอ

ภาษาบนหน้าจอ: ภาษาเวียดนามที่เรียบง่าย ตรงประเด็น ไม่เป็นวิชาการ ไม่ใช้คะแนนรวมที่อ่านยาก (บอกแค่ว่า "ส่วนใหญ่เชิงบวก / เชิงลบ / เป็นกลาง", "เรื่องที่ต้องจับตา")

## 2. แหล่งข้อมูลและขอบเขต

รายชื่อแหล่งที่มาและสถานะการเก็บข้อมูลอยู่ใน `public/data/sources.json` แท็บ **ตามแหล่งที่มา** จะแสดงทุกแหล่งเสมอ แม้แหล่งที่ยังไม่มีข้อมูล เพื่อไม่ให้สับสนระหว่าง "ความคิดเห็น 0 รายการ" กับ "ยังไม่ได้เก็บข้อมูล"

| แหล่งที่มา | สิ่งที่เก็บ |
|---|---|

| YouTube | เฉพาะวิดีโอภาษาไทย (มีข้อความไทยในชื่อหรือคำอธิบาย) วิดีโอของครีเอเตอร์/ผู้เล่นนับเป็น 1 ความคิดเห็นต่อคลิป บวกคอมเมนต์ของผู้ชม วิดีโอจากช่องทางการ `Play Together VNG TH`: เก็บเฉพาะคอมเมนต์ ข้ามคอมเมนต์ของเจ้าของช่อง และคอมเมนต์ที่มีแค่ลิงก์/คำทักทาย/โปรโมต |

สถานะแหล่งที่มา: `full` (ครบ 30 วัน), `partial` (บางส่วน), `pending` (กลุ่มปิดที่รออนุมัติ), `not_collected`, `inactive` (ไม่มีโพสต์ใหม่), `youtube`, `tiktok`, `store`

## 3. กฎของข้อมูล (บังคับ)

1. ห้ามเขียนทับหรือลบความคิดเห็นที่มีอยู่แล้ว การนำเข้าทุกครั้งต้องเทียบจำนวนรายการก่อน/หลัง id เก่าทั้งหมดต้องยังอยู่ และคำแปลเก่าต้องไม่เปลี่ยน
2. ปิดบังชื่อผู้โพสต์/ชื่อช่องเป็น `X***` ลบเบอร์โทร LINE ID อีเมล และชื่อคนที่ถูกแท็ก ห้ามเก็บคุกกี้ โทเค็น หรือข้อมูลส่วนบุคคลไว้ใน repo
3. เนื้อหาที่ไม่รู้วันที่โพสต์ (`date_basis=observed_at`) จะแยกไว้ต่างหากและ **ไม่** นับในสถิติรายวัน จะแสดงในรายการความคิดเห็นเฉพาะตอนเปิดตัวเลือกนี้เท่านั้น
4. ตัวเลขและข้อสรุปทุกอย่างคำนวณใหม่ตามช่วงเวลาที่เลือก และเทียบกับช่วงก่อนหน้าที่ยาวเท่ากัน เมื่อดูแบบ 1 วัน กราฟยังแสดง 30 วันก่อนหน้าเพื่อให้เห็นบริบท
5. ช่วงก่อนหน้ามีความคิดเห็นไม่ถึง 10 รายการ → เทียบด้วยตัวเลขจริง ต่างกัน ≥ 5 เท่า → เพิ่มหมายเหตุ "อาจเป็นเพราะขอบเขตการเก็บข้อมูลต่างกัน"
6. `ค้างคาว` หมายถึง **ค้างคาว (สัตว์)** ไม่ใช่เกมค้าง (มี regression test ตรวจอยู่)
7. วันที่และเวลาใช้ Asia/Bangkok (UTC+7) คอมเมนต์ YouTube เก่ามีแค่วันที่โดยประมาณ (`date_precision=approximate`)

## 4. การติดป้ายให้แต่ละความคิดเห็น

แต่ละรายการมีฟิลด์ดังนี้:

- `sentiment`: `Positive`, `Negative`, `Neutral`, `Mixed` โพสต์ขายของและคำถามทั่วไป = เป็นกลาง
- `intent` (ประเภทเนื้อหา คือผู้เล่นกำลังทำอะไร): `question` คำถาม / ขอความช่วยเหลือ · `answer` คำตอบ / ไกด์ · `share` แชร์ / อวด · `event_entry` ส่งผลงานกิจกรรม · `bug` แจ้งบั๊ก · `performance` เกมเด้ง / แลค / ประสิทธิภาพ · `account` บัญชี / ล็อกอิน · `complaint` ร้องเรียน · `suggestion` ข้อเสนอแนะ · `praise` ชม / ชอบ · `trade` ซื้อ / ขาย / แลกเปลี่ยน · `social` หาเพื่อน / สังสรรค์ · `chat` คุยทั่วไป
- `keywords`: คีย์เวิร์ดภาษาเวียดนาม 1–4 คำ ตัวพิมพ์เล็ก ใช้ชุดคีย์เวิร์ดมาตรฐานเป็นหลัก (câu cá, cá hiếm, trồng trọt, rau khổng lồ, nhân sâm, thú cưng, trang phục, bộ sưu tập thẻ, sự kiện, halloween, đảo kaia, cập nhật mới, code quà tặng, vvip pass, gacha, kim cương, nạp tiền, giá vật phẩm, chuyển tài khoản vng, đăng nhập, mất dữ liệu, văng game, lag, kẹt nhân vật, mua bán vật phẩm, cày thuê, đổi thời tiết, tìm bạn, quảng cáo…) คำที่สะกดต่างกันจะถูกรวมใน `scripts/apply-labels.mjs`
- `summary_vn`: ประโยคสั้นๆ 1 ประโยคว่าผู้เล่นพูด/ทำอะไร
- `label_method=ai_review`, `needs_review=true`: ป้ายที่ AI ติดตามแนวทางที่กำหนดไว้ ต้องมีคนตรวจ sentiment ก่อนตรวจจะเก็บไว้ใน `sentiment_rule`
- ฟิลด์เก่ายังเก็บไว้: `theme`, `topic`, `activity_type` (ป้ายจากกฎคีย์เวิร์ด), `content_kind` (post/comment/review/video)

"สิ่งที่ผู้เล่นชอบ / ไม่พอใจ" จัดอันดับตามคีย์เวิร์ด และไม่รวม `trade` "ต้องดำเนินการ" รวมการแจ้งเตือน P0/P1 ในข้อมูล และกลุ่ม `bug`, `performance`, `account`, `complaint` พร้อมคำแนะนำจาก `public/data/facebook-insights.json`

## 4b. กฎการแปลไทย → เวียดนาม

คำแปลต้องอ่านครั้งเดียวเข้าใจ และเข้ากับบริบทของเกม ไม่แปลคำต่อคำแบบ Google Translate คู่มือฉบับเต็มและอภิธานศัพท์: `docs/translation-guide.md` ใน repository

- แปลตามความหมาย เป็นประโยคที่เป็นธรรมชาติเหมือนผู้เล่นเวียดนามคุยกันในกลุ่มเกม รักษาน้ำเสียงเดิม (บ่น ล้อเล่น ถามด่วน) และไม่เติมข้อมูลเพิ่ม
- ใช้บริบทช่วย: แหล่งที่มา (ในกลุ่มซื้อขาย โพสต์ส่วนใหญ่คือขายของ) ประเภทเนื้อหา และสรุป เพื่อเข้าใจประโยคสั้นหรือประโยคที่ขาดหายได้ถูกต้อง
- ตัดคำลงท้ายสุภาพ (ครับ/ค่ะ/นะ/งับ) หรือเปลี่ยนเป็น "ạ/nhé/nha"; `555` = "haha"
- คง `[redacted]` ราคาแบบ "10 baht" จำนวน และชื่อเฉพาะภาษาอังกฤษ (Golden Chain, VVIP Pass, Halloween, Kaia) ไว้ รายการขายของให้สั้นและเป็นข้อๆ
- ไม่แน่ใจคำสแลง: แปลตามความหมายในเกมที่สมเหตุสมผลที่สุด ถ้าไม่ชัดจริงๆ ให้ใส่ "(?)"
- รีวิวในสโตร์แปลแบบเต็ม (ไม่สรุป)
- คำที่พบบ่อย (คำไทย = คำแปลภาษาเวียดนามที่ใช้): โสม = nhân sâm (น้ำค้าง sương, แสงจันทร์ ánh trăng, ออโรร่า cực quang); ติดสถานะ = có hiệu ứng đặc biệt (มีเอฟเฟกต์พิเศษ); รับฟาร์ม / รับขุด = cày thuê (บริการรับจ้างปั๊ม); คิวว่าง = nhận đơn (รับออเดอร์); ทัก = nhắn mình (ทักมาได้); บริการกดสภาพอากาศ = dịch vụ đổi thời tiết; เงินฟาร์ม = tiền nông trại; ทอง = vàng; เพชร = kim cương; กาชา / สุ่ม = gacha / quay; ย้ายข้อมูล / ย้ายไอดี = chuyển dữ liệu / tài khoản sang VNG; บัค = lỗi; หลุด / เด้ง = văng game; แลค = lag; ค้าง = treo game (เฉพาะเมื่อพูดถึงเกม) — **ค้างคาว = con dơi (ค้างคาว สัตว์)**; เวล = cấp độ; ไอดี = tài khoản
- คำแปลตามบริบทจะมี `translation_method=ai_contextual` คำแปลเครื่องแบบเก่าเก็บไว้ใน `text_vn_machine` เพื่อใช้เทียบ นำคำแปลใหม่ไปใช้ด้วย `node scripts/apply-translations.mjs <file.json>`

## 4c. ปุ่มสลับ VI / EN

- ปุ่ม **EN / VI** ด้านบน (ข้างปุ่ม ?) สลับทั้งแดชบอร์ดเป็นภาษาอังกฤษและกลับมา เบราว์เซอร์จะจำตัวเลือกไว้ `?lang=en` เปิดเป็นภาษาอังกฤษได้ทันที
- ภาษาเวียดนามเป็นข้อความหลักเสมอและไม่ถูกเขียนทับ เวอร์ชันภาษาอังกฤษของแต่ละความคิดเห็นอยู่ในฟิลด์แยก `text_en` / `summary_en` ถ้าไม่มี มุมมอง EN จะแสดงภาษาเวียดนามแทน ต้นฉบับภาษาไทยเหมือนเดิมทั้งสองโหมด
- ข้อความหน้าจอภาษาอังกฤษอยู่ใน `public/i18n/en.json`: `ui` เก็บข้อความหน้าจอ (ตัวเลขแทนด้วย `{0}`, `{1}`… คำศัพท์ข้อมูลแทนด้วย `{t0}`…) `terms` เก็บคีย์เวิร์ด ธีม และชื่อแหล่งที่มา ข้อความที่ยังไม่มีคำแปลจะแสดงเป็นภาษาเวียดนาม ในโหมด EN ใช้ `window.__i18n.miss` ใน console เพื่อดูรายการที่ยังขาด
- สไตล์ภาษาอังกฤษ: เรียบง่าย อ่านง่าย ไม่เป็นวิชาการ
- เมื่อเพิ่มความคิดเห็นใหม่: แปลเป็นภาษาอังกฤษด้วย แล้วนำไปใช้ด้วย `node scripts/apply-english.mjs <file.json>` (รูปแบบ `{ "<id>": { "text": "...", "summary": "..." } }`) และเพิ่มคีย์เวิร์ดใหม่ลงใน `terms` ของ `en.json`

## 4d. บริบทของเกมและขอบเขตการดูแล

- AI ติดป้ายความคิดเห็นโดยใช้ `docs/game-context.md` ซึ่งทีมดูแลเกมจะเพิ่มข้อมูลเกี่ยวกับเกมไปเรื่อยๆ เพื่อให้ผลลัพธ์ตรงกับเกมมากขึ้นเมื่อเวลาผ่านไป
- **เกมนี้ไม่มี APK** (มีเฉพาะบน Google Play และ App Store) โพสต์ที่พูดถึงปัญหาตอนติดตั้ง APK หรือเวอร์ชันจากเว็บที่ไม่เป็นทางการยังเก็บไว้ แต่จะได้ `out_of_scope: "unofficial_apk"` แดชบอร์ดจะติดแท็ก "นอกขอบเขต: APK เถื่อน" และ **ไม่** นับใน "ต้องดำเนินการ" / "ความคิดเห็นที่ต้องตรวจ"
- ติดหรือเอาแท็กออกเอง: `node scripts/set-scope.mjs unofficial_apk <id>` / `node scripts/set-scope.mjs clear <id>` ถ้ามีกฎใหม่ ให้เพิ่มใน `docs/game-context.md` และใน `RULES` ของ `scripts/set-scope.mjs`

## 5. หน้าจอ

- **ภาพรวม** (ตัวเลขสำคัญอยู่ด้านบน แนวโน้มอยู่ตรงกลาง รายละเอียดอยู่ด้านล่าง): แถว KPI 5 ใบ (ความคิดเห็นทั้งหมด, % เชิงบวก, % เชิงลบ, ต้องดำเนินการ = บั๊ก + เกมเด้ง/แลค + บัญชี + ร้องเรียน, คะแนนสโตร์ของแอป VNG) แต่ละการ์ดมีค่าเปลี่ยนแปลงและ sparkline คลิกเพื่อไปดูรายละเอียด; ไฮไลต์ 3 บรรทัด + สรุปเต็มที่พับเก็บได้ + ปุ่มคัดลอกรายงาน; แนวโน้มรายวัน (ตาม sentiment หรือประเภทเนื้อหา, รายวัน/รายสัปดาห์, จำนวน/%; คลิกแท่งเพื่อเปิดรายการของวันนั้น) และกราฟวงกลม sentiment; ผู้เล่นกำลังทำอะไร และคีย์เวิร์ดยอดนิยม (แท่งจัดอันดับ สีแสดงสัดส่วน sentiment); สิ่งที่ผู้เล่นชอบ / ไม่พอใจ / ต้องดำเนินการ (แบบกระชับ คลิกเพื่ออ่าน); heatmap คีย์เวิร์ดรายวัน (คลิกช่องเพื่อกรองตามวัน + คีย์เวิร์ดนั้น) หมายเหตุโดยละเอียดอยู่ในไอคอน ⓘ
- **คีย์เวิร์ดตามแหล่งที่มา** (ในภาพรวมและตามแหล่งที่มา): หนึ่งคอลัมน์ต่อหนึ่งประเภทแหล่ง (กลุ่ม Facebook, แฟนเพจ, YouTube, TikTok, LINE OpenChat, สโตร์) พร้อมคีย์เวิร์ดที่ถูกพูดถึงมากที่สุดในช่วงนั้น คลิกเพื่อกรองรายการตามประเภทแหล่ง + คีย์เวิร์ด (ตัวกรองแหล่งที่มามีกลุ่ม "ตามประเภทแหล่ง")
- **ตามแหล่งที่มา**: แถว KPI (จำนวนแหล่งที่มีความคิดเห็น, แหล่งที่ใหญ่ที่สุด, สัดส่วน Facebook/YouTube/สโตร์, แหล่งที่เชิงลบมากที่สุด) กราฟวงกลมสัดส่วนการพูดถึง sentiment ตามแหล่ง การ์ดของแต่ละแหล่ง รายชื่อแหล่งที่ไม่มีข้อมูล (พับเก็บไว้) ตารางตามแหล่งและตามวัน
- **รีวิวในสโตร์**: แถว KPI คะแนนแอป VNG (Google Play, App Store, เรตติ้งใหม่) กราฟคะแนนรายสัปดาห์ ตารางตามแอป KPI รีวิวของช่วงเวลานั้น การกระจายดาว รีวิวชม / ร้องเรียน / ดาวไม่ตรงกับเนื้อหา
- **รายการความคิดเห็น**: การ์ดเรียงจากใหม่ไปเก่า แต่ละการ์ดมี sentiment ประเภทเนื้อหา แหล่งที่มา สรุป คำแปล ต้นฉบับ (คลิกเพื่อเปิด) คีย์เวิร์ด (คลิกเพื่อกรอง) และลิงก์; ชิปกรองด่วนตาม sentiment; ตัวกรองตามวันที่ แหล่งที่มา sentiment ประเภทเนื้อหา คีย์เวิร์ด และค้นหาข้อความ; ดาวน์โหลด CSV
- ชิป/การ์ด/ตารางที่คลิกได้ทุกอันจะกรองไปยังรายการความคิดเห็น ลิงก์แชร์ได้ของแต่ละแท็บ: `#overview`, `#sources`, `#store`, `#feedback`

## 6. โครงสร้างไฟล์

- `public/index.html`: หน้าจอและลอจิกทั้งหมด (vanilla JS + Chart.js 4.4.1)
- `public/data/index.json`: รายการวันที่มีข้อมูล `public/data/daily/YYYY-MM-DD.json`: ความคิดเห็น คะแนน การแจ้งเตือน และตัวชี้วัดของแต่ละวัน
- `public/data/sources.json`: รายชื่อแหล่งที่มา ชื่อที่แสดง และสถานะ `public/data/themes.json`: พจนานุกรมธีมแบบเก่า `public/data/facebook-insights.json`: คำแนะนำการดำเนินการ
- `scripts/import-facebook.mjs`: นำเข้า staging ของ Facebook (**แทนที่รายการ Facebook ทั้งหมดด้วยข้อมูล staging** → ต้องรวม staging เก่า + ใหม่ก่อนรันทุกครั้ง; คงคำแปลและป้ายเก่าไว้โดยใช้คีย์ ลิงก์+เนื้อหา+ผู้โพสต์)
- `scripts/translate-facebook-vietnamese.mjs`: แปลรายการ Facebook ที่ยังไม่มีภาษาเวียดนาม (แคช `.staging/translations-vi.json`)
- `scripts/import-youtube.mjs`, `scripts/import-tiktok.mjs`: เพิ่ม/อัปเดตรายการ `source=YouTube` / `source=TikTok` ตาม id โดยไม่แตะแหล่งอื่น
- `scripts/import-sensortower-vng.mjs`: **ใช้สคริปต์นี้** กับไฟล์ export ใหม่จาก Sensor Tower (คะแนนรายวัน + รีวิวแอป VNG ที่แปลและติดป้ายแล้ว) รวมข้อมูลอย่างปลอดภัย: จะแทนที่สแนปช็อตรายสัปดาห์ก็ต่อเมื่อยอดเรตติ้งใหม่รวมตรงกับข้อมูลรายวัน; รีวิวเพิ่ม/อัปเดตตาม id
- `scripts/import-sensortower-ratings.mjs`, `import-sensortower-android.mjs`, `import-sensortower-ios.mjs`: ตัวนำเข้าแบบเก่า **ลบคะแนน/รีวิวประเภทเดียวกันทั้งหมดแล้วเขียนใหม่**; ห้ามรันซ้ำกับไฟล์ที่ครอบคลุมแค่บางช่วงวันที่
- `scripts/apply-labels.mjs`: นำป้าย intent/keywords/summary จากไฟล์ JSON ไปใช้
- `scripts/apply-translations.mjs`: นำคำแปลตามบริบทไปใช้ (เก็บคำแปลเก่าไว้ใน `text_vn_machine`) `docs/translation-guide.md`: กฎการแปลและอภิธานศัพท์
- `scripts/validate-data.mjs` + `test/*.mjs`: ตรวจข้อมูลและหน้าจอ `.staging/` ถูก git-ignore

## 7. ขั้นตอนการอัปเดต

1. เก็บข้อมูล (กลุ่ม Facebook ผ่านเบราว์เซอร์ที่ล็อกอินไว้; YouTube ผ่านการค้นหาภูมิภาค TH และ RSS ของช่อง; ไฟล์ export จาก Sensor Tower)
2. ทำความสะอาด → staging JSON ใน `.staging/` (ปิดบังชื่อผู้โพสต์ ไม่มีข้อมูลส่วนบุคคล)
3. นำเข้าด้วยสคริปต์ที่ตรงกัน เทียบจำนวนรายการก่อน/หลัง (ไม่มี id หาย ไม่มีคำแปลเก่าเปลี่ยน)
4. แปลส่วนที่ขาดตาม `docs/translation-guide.md` (ไม่แปลคำต่อคำ) ใส่ `intent`, `keywords`, `summary_vn` และตรวจ `sentiment` ของรายการใหม่ แล้วรัน `apply-labels.mjs`
5. แปลรายการใหม่เป็นภาษาอังกฤษ (`apply-english.mjs`) และเพิ่มคีย์เวิร์ดใหม่ลงใน `public/i18n/en.json`
6. อัปเดต `sources.json` ถ้าขอบเขตการเก็บข้อมูลเปลี่ยน
7. `npm run check` (validator + tests) ต้องผ่าน ทุกรายการต้องติดป้ายแล้ว
8. Commit และ push `main` แล้ว GitHub Actions จะดีพลอยให้อัตโนมัติ

### การรันอัตโนมัติรายวัน

- ทุกวันเวลา **06:00 น.** (เวลาเครื่อง อาจเริ่มช้าไปไม่กี่นาที) งาน Claude desktop `ptg-th-daily-feedback` จะเก็บความคิดเห็นของ **วันก่อนหน้า** (กลุ่ม Facebook, แฟนเพจไทย, YouTube, TikTok) จากหน้าต่าง Chrome ที่ผู้ใช้เปิดและล็อกอินทิ้งไว้ จากนั้นอัปเดตข้อมูล รันการตรวจสอบ commit และ push
- **เก็บย้อนวันที่ขาด**: ทุกครั้งที่รันจะเริ่มด้วย `node scripts/check-gaps.mjs` และดูกราฟ 30 วัน วันไหนใน 14 วันล่าสุดที่ไม่มีการรันเก็บข้อมูลหรือไม่มีความคิดเห็นจากคอมมูนิตี้ จะถูกเก็บให้ครบก่อนเมื่อวาน
- **ไม่** แตะ Sensor Tower: คะแนน/รีวิวในสโตร์นำเข้าด้วยมือด้วย `import-sensortower-vng.mjs`
- **รายชื่อครีเอเตอร์ของทีมการตลาด** (Play Together Creators 2026-2027, กลุ่ม `creator_list_2026`) อยู่ใน `docs/collection-targets.json` มีแค่แฮนเดิล/ลิงก์/เกมหลัก (ไม่มีอีเมลหรือราคา) การรันแต่ละครั้งจะไล่สแกนกลุ่มนี้แบบหมุนเวียน และหาครีเอเตอร์ **ที่คล้ายกัน** ทุกวัน (บัญชีคล้ายกัน ช่องที่ถูกแนะนำ คอลแลบ แฮชแท็กเกมหลัก + Play Together)
- **หาแหล่งใหม่** ทุกครั้งที่รัน: กลุ่ม Facebook ช่อง YouTube และครีเอเตอร์ TikTok ใหม่ที่พูดถึง Play Together เป็นภาษาไทยและมีความเคลื่อนไหวใน 30 วันล่าสุด จะถูกเพิ่มด้วย `scripts/add-source.mjs` (กลุ่มไปที่ `public/data/sources.json` ช่อง/ครีเอเตอร์ไปที่ `docs/collection-targets.json`) กลุ่มปิดจะได้สถานะ **เพิ่งพบ · ต้องขอเข้าร่วม** เพื่อให้ผู้ใช้กดเข้าร่วม แหล่งที่ไม่เหมาะจะไปอยู่ใน `rejected` เพื่อไม่ต้องตรวจซ้ำ
- ขั้นตอนโดยละเอียด: `docs/daily-collection.md` นำเข้าด้วย `scripts/import-daily.mjs` (เพิ่มอย่างเดียว ข้ามรายการซ้ำ ถ้ามีรายการไม่ถูกต้องแม้แต่รายการเดียวจะปฏิเสธทั้งชุด) `scripts/receive-staging.mjs` รับข้อมูลจากหน้า Facebook ผ่าน form POST
- หน้าจอล็อกอิน / 2FA / CAPTCHA จะถูกบันทึกเป็น `blocked` และไม่จัดการอัตโนมัติเด็ดขาด ผลของการรันแต่ละครั้งอยู่ใน `public/data/collection-runs/<date>.json`
- ต้องเปิดแอป Claude ไว้ตอน 06:00 ถ้าปิดอยู่ งานจะรันเมื่อเปิดแอปอีกครั้ง

## 8. หมายเหตุสำหรับ AI ที่ทำโปรเจกต์ต่อ

- อ่านคู่มือนี้ README.md และ `test/dashboard-default.test.mjs` ก่อนแก้ไข
- ห้ามเดาวันที่โพสต์ ห้ามรวมแอป VNG กับแอป Global ห้ามนับโพสต์ของแฟนเพจ/ช่องทางการเป็นความคิดเห็นของผู้เล่น
- เมื่อเพิ่มแหล่งใหม่: เพิ่มใน `sources.json` (มีเทสต์ที่บังคับว่าทุกแหล่งในข้อมูลต้องอยู่ในรายการ) และเขียนกฎของแหล่งนั้นไว้ในคู่มือนี้และใน README
- เมื่อแก้หน้าจอ: ใช้ภาษาเวียดนามที่เรียบง่าย ตรงประเด็น ตรวจบนเดสก์ท็อป มือถือ (375px) โหมดมืด และต้องไม่มีการล้นแนวนอน

## เลย์เอาต์รายงานบนเดสก์ท็อปและมือถือ

- ภาพรวมเริ่มด้วยข้อสรุปและ **ตรวจก่อน** การแจ้งเตือน P0/P1 นับแยกจากความคิดเห็นเรื่องบั๊ก เกมเด้ง/แลค บัญชี และร้องเรียน ความคิดเห็นที่ต้องตรวจไม่ใช่จำนวนข้อบกพร่องของเกมที่ยืนยันแล้ว
- **อ่านความคิดเห็นที่ต้องตรวจ** เปิดรายการที่กรองตามสี่กลุ่มนั้น **ดูการแจ้งเตือน** ขยายส่วนที่ต้องดำเนินการ การเปลี่ยนแปลงสัดส่วนเชิงบวก/เชิงลบใช้หน่วยจุดเปอร์เซ็นต์ ช่วงก่อนหน้าที่มีไม่ถึง 10 รายการยังใช้การเปลี่ยนแปลงแบบจำนวนจริง
- บนมือถือยังมีครบทั้งสี่แท็บแต่ใช้ชื่อสั้น การ์ดแหล่งที่มาแถวละหนึ่งใบ และส่วนขอบเขตการเก็บข้อมูลขยายดูได้ ช่องค้นหาแสดงอยู่ตลอด ตัวกรองขั้นสูงพับเก็บไว้ แต่ตัวกรองที่ใช้อยู่ยังทำงานและมองเห็นได้นอกแผง
- บนมือถือแสดงกิจกรรม/คีย์เวิร์ด 5 อันดับแรกก่อน พร้อมปุ่ม **แสดงทั้งหมด** ตารางคีย์เวิร์ดรายวันขยายเมื่อต้องการ ข้อมูลและผลการกรองเหมือนกันทุกขนาดหน้าจอ
- ปุ่มคำอธิบายใช้ได้ทั้งการแตะและคีย์บอร์ด การ์ด KPI รองรับ Enter/Space ปุ่มควบคุมหลักบนมือถือมีพื้นที่แตะ 44px
